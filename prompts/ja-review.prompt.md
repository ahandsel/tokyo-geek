# 日本語文章校正


## 対象

* **このリポジトリの日本語コンテンツ**（`contents/ja/` の旅行ガイド、生活情報、技術記事）、日本語ドキュメント（`docs/` など）、およびユーザーが貼り付けた日本語テキスト。
* 入力はテキストまたはファイル。UTF-8 を前提。
* コンテンツページを校正する場合、frontmatter（`title`、`description`、`localization`）の構造は変更しない。`title` と `description` の日本語は校正対象。


## 参照するスタイルガイド

* 第一に [docs/general-style-guide-japanese.md](../docs/general-style-guide-japanese.md) に従う。以下の「優先順位」の既定は同ガイドの要約であり、食い違う場合はガイドが優先。
* 用語の対訳は [docs/glossary.yaml](../docs/glossary.yaml) を参照。
* ヘルプドキュメント形式のページは [docs/technical-style-guide-japanese.md](../docs/technical-style-guide-japanese.md) も適用。
* 参考既定は JTF 日本語標準スタイルガイドおよび「公用文作成の考え方」に整合。


## 優先順位（上から順）

1. **誤字脱字**：明白な誤りを修正。
2. **文法**：主述のねじれ、助詞、敬体と常体の不整合を修正。
3. **表記統一（ガイドの既定）**：
   * 数字と英字は半角、句読点は全角の`、`と`。`、引用にはカギ括弧（`「」`と`『』`）を使う。
   * 英数字と日本語文字の間に半角スペースを入れない（例：`保存済みのPDFファイル（3件）を開く`）。
   * 外来語の語尾の長音記号は省略しない（例：`ユーザー`、`サーバー`）。
   * 使わない記号：強調の感嘆符、米印`※`、隅付き括弧`【】`、角括弧`[]`、アンドマーク`&`、ダブルクオートとシングルクオート。「または」「および」の意味のスラッシュも使わない。
   * 常用漢字表にない読み方は使わず、ひらがなにしたほうが読みやすい漢字はひらがなで書く（例：`しばらくの間ご利用いただけません`）。
   * 数えられる語句は半角の算用数字、熟語や固有名詞は漢数字（例：`3回目で合格`、`世界一`、`九州`）。
4. **冗長表現の解消**：`〜することができる`は`できる`に、動詞の名詞化と敬語の多用を避ける。安易なカタカナ語は日本語に言い換える。
5. **文脈の整合**：不自然な接続、論理の飛躍、二重否定を検出し修正案を提示。能動態を基本とし、結果に焦点を当てる場合のみ受動態を使う。
6. **語彙の適切さと一貫性**：同義表現のばらつきを統一。感覚的な特徴のみに頼る表現を避ける。
7. **可読性（構文）**：長文の分割、並列表現の整形、段落構成の整理。


## 出力仕様（この順で必ず出力）

1. **要約（3 行以内）**：全体の診断結果と主要修正点。
2. **重大修正**：文法や意味変化を伴う修正を箇条書きで列挙（根拠つき）。
3. **表記統一一覧**：今回適用した統一ルールの差分（例：「半角数字に統一」「全角カギ括弧に統一」）。
4. **修正前と修正後（抜粋）**：重要箇所だけを以下形式で示す。**変更部分は太字**。
   * 例  
     修正前：「A の**実装**は...」  
     修正後：「A の**実施**は...」  
     理由：語義の不一致を解消。
5. **改訂版（全文）**：校正済み本文を提示。必要に応じてトーン（敬体と常体）を統一。
6. **差分ビュー（任意）**：`diff` 風または Markdown 比較。機密が含まれる場合は省略。
7. **確認事項（任意）**：判断が割れる箇所は既定で処理し、代替案や選択肢を提示。


## 手順

1. 入力の文字コードと文末表記（`。`と`.`）を検査して正規化。
2. 優先順位に沿って機械的チェック、文脈チェック、語彙と構文の順に適用。
3. 曖昧な点があっても作業は**停止しない**。既定値で進め、必要なら「確認事項」に列挙。
4. 固有名詞、数値、日付は改変しない。出典がない推測はしない。
5. ファイルを直接編集した場合は、最後に `pnpm lint-target <ファイルパス>` を実行して整形を確定する。


## トーン既定

* 既定は**敬体（です・ます調）の会話体**。スタイルガイドの基本ルールに合わせ、シンプルで平易な表現を使う。
* 依頼があれば常体へ一括変換（`notes/` の個人メモなどに適する）。
* 英数字表記、見出しレベル、箇条書き記号は文書内で一貫。


## 例（フォーマット）

【修正例】  
修正前：`浅草寺は、東京を代表する観光スポットとして知られており、訪問することが可能です！`  
修正後：`浅草寺は、東京を代表する観光スポットです。いつでも訪問できます。`  
理由：冗長表現（`〜することが可能`）の解消と、強調の感嘆符の削除。


## 制約

* コードやコマンドは実行しない（上記の `pnpm lint-target` を除く）。必要なら擬似コードや手順のみ提示。
* 外部送信や外部サイト閲覧はユーザーが明示した場合のみ行う。
* `contents/ja/` の `localization: sync` のページを編集した場合、対になる `contents/en/` 側の `localization` を `TODO: drifted` に更新する必要があることをユーザーに伝える。
